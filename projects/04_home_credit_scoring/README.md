# Кредитный скоринг: Home Credit Default Risk

Учебный проект по данным соревнования [Home Credit Default Risk](https://www.kaggle.com/competitions/home-credit-default-risk/overview). Задача - предсказать вероятность того, что у клиента возникнут сложности с выплатой кредита.

Основная метрика - ROC-AUC. В качестве дополнительных метрик используются PR-AUC и Brier score: они помогают увидеть качество на несбалансированных классах и калибровку вероятностей.

## Что сделано

Вся работа находится в одном [финальном ноутбуке](notebooks/home_credit_scoring_final.ipynb). В нём последовательно выполнены:

- EDA основной анкеты: классовый дисбаланс, пропуски, аномалии, распределения дохода и возраста;
- проверка покрытия и гранулярности пяти исторических источников;
- feature engineering по анкете, бюро, прошлым заявкам, POS, платежам и кредитным картам;
- leakage-audit: контроль уникальности ключей, схемы train/test, отсутствия `TARGET` в матрице и бесконечных значений;
- сравнение логистической регрессии, одиночного дерева, LightGBM, CatBoost и MLP;
- настройка LightGBM через Optuna, ablation study, OOF-анализ ошибок, SHAP и fairness-диагностика;
- cross-fitted blend из LightGBM, CatBoost и MLP, после которого создаётся Kaggle submission.

## Результаты текущего запуска

Полная feature matrix содержит `1 476` признаков. Все оценки получены по одной 5-fold OOF-валидации.

| Модель | ROC-AUC | PR-AUC | Brier score |
| --- | ---: | ---: | ---: |
| OOF blend | 0.79299 | 0.28966 | 0.06542 |
| CatBoost с историей | 0.79279 | 0.28916 | 0.06546 |
| LightGBM с историей | 0.77955 | 0.27174 | 0.06651 |
| LightGBM только по анкете | 0.76741 | 0.25278 | 0.06732 |
| MLP с историей | 0.75903 | 0.24024 | 0.19482 |
| Логистическая регрессия | 0.75126 | 0.23164 | 0.20195 |

Исторические данные повысили ROC-AUC LightGBM на `+0.01213` относительно варианта только с текущей анкетой. В ablation study наиболее полезными оказались платёжная история (`-0.00696` ROC-AUC без неё) и данные бюро (`-0.00599`).

Финальный blend использует веса `0.90` для CatBoost, `0.08` для LightGBM и `0.02` для MLP. Его преимущество над CatBoost составляет всего `+0.00020` ROC-AUC, поэтому CatBoost остаётся сопоставимым и более простым ориентиром. Submission создаётся в notebook как `submissions/submission_oof_blend.csv`.

## Данные

Используются все таблицы из архива соревнования:

| Источник | Роль |
| --- | --- |
| `application_train.csv`, `application_test.csv` | Анкеты клиентов; в train есть целевая переменная `TARGET` |
| `bureau.csv`, `bureau_balance.csv` | История кредитов клиента в других организациях |
| `previous_application.csv` | Предыдущие заявки в Home Credit |
| `POS_CASH_balance.csv` | История POS- и cash-кредитов |
| `installments_payments.csv` | История платежей по рассрочке |
| `credit_card_balance.csv` | Поведение по кредитным картам |

Во всех внешних таблицах строки сначала агрегируются до уровня `SK_ID_CURR`, и только затем присоединяются к анкете. Это не позволяет размножить заявки при merge. Отсутствие записи в истории сохраняется как признак: оно может означать, что у клиента не было соответствующего продукта.

## Модели и валидация

Для сравнения используется один и тот же `StratifiedKFold` из пяти фолдов. ROC-AUC считается только на внешнем validation-фолде.

У бустингов и MLP внешний фолд не используется для ранней остановки. Внутри его train-части создаётся отдельный стратифицированный holdout для выбора числа итераций или эпох. Так OOF-прогноз действительно получен моделью, не видевшей ни метки, ни особенностей настройки этой строки.

Весы финального blend оцениваются cross-fitted способом: для каждого validation-фолда веса подбираются на остальных OOF-строках, а итоговые веса для test получают уже после оценки качества. Public leaderboard не используется для выбора модели или весов.

## Запуск

1. Скачать данные соревнования и разместить CSV в `data/raw/`.
2. В conda-окружении, выбранном как Jupyter kernel, установить CUDA-сборку LightGBM:

   ```bash
   conda install -c conda-forge lightgbm
   ```

3. Установить остальные зависимости:

   ```powershell
   pip install -r requirements.txt
   ```

4. Открыть проект в VS Code или Jupyter и выполнить `notebooks/home_credit_scoring_final.ipynb` сверху вниз.

Notebook запускает полный эксперимент сразу: пять CV-фолдов, 40 итераций Optuna, ablation study, SHAP, fairness-диагностику и финальный ансамбль. Для запуска нужен Python kernel с доступным CUDA GPU. CatBoost, MLP и CUDA-реализация LightGBM используют GPU; перед обучением notebook выполняет короткую проверку LightGBM CUDA.

После завершения появятся таблица OOF-метрик, графики интерпретации и файл `submissions/submission_oof_blend.csv`. На Kaggle достаточно добавить Competition Data **Home Credit Default Risk**, включить GPU и выполнить все ячейки.

## Ограничения

Проект показывает качество ранжирования в конкурсной постановке. Он не доказывает причинность признаков и не готов для реального кредитного решения без отдельной проверки временной стабильности, калибровки вероятностей, юридических требований и fairness на релевантных защищаемых группах.
