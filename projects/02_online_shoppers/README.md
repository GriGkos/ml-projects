# Online Shoppers Purchasing Intention

В этой работе я исследовал данные о сессиях интернет-магазина и проверил, можно ли по поведению пользователя предсказать, закончится ли сессия покупкой.

## Датасет

Использован датасет [Online Shoppers Purchasing Intention](https://www.kaggle.com/datasets/imakash3011/online-shoppers-purchasing-intention-dataset).

Я выбрал его, потому что в нём есть и числовые, и категориальные признаки, а покупки встречаются заметно реже обычных сессий. На таких данных можно проверить разные способы подготовки признаков и сравнить линейную модель с деревьями.

В исходном файле было 12 330 строк и 18 столбцов. Пропусков нет. Перед разбиением данных я удалил 125 полных дубликатов, поэтому в работе осталось 12 205 строк. Доля сессий с покупкой составляет около 15,6%.

Целевая переменная - `Revenue`:

- `0` - сессия не закончилась покупкой;
- `1` - во время сессии была покупка.

## Что сделано в работе

Сначала я проверил структуру данных, пропуски, дубликаты, распределения признаков, баланс классов и корреляции. Гипотезы формулировались по ходу EDA.

После удаления дубликатов данные были разделены на train и test. EDA с использованием целевой переменной, подбор параметров и проверка гипотез проводились только на train. Test использовался один раз в конце для финального сравнения моделей.

Категориальные признаки кодировались через One-Hot Encoding. Для Logistic Regression числовые признаки масштабировались. Все преобразования находились внутри `Pipeline`, поэтому на каждом фолде кросс-валидации они обучались только на соответствующей обучающей части.

Были обучены три модели:

- Logistic Regression;
- Random Forest;
- Gradient Boosting.

Параметры подбирались через `GridSearchCV` с пятифолдовой стратифицированной кросс-валидацией. Основной метрикой был ROC-AUC. Дополнительно считались Average Precision, precision, recall и F1.

## Гипотезы и результаты

### H1. Балансировка классов повысит recall, но снизит precision

Гипотеза подтвердилась.

При `class_weight="balanced"` средний recall Logistic Regression вырос с 0.370 до 0.757, а precision снизился с 0.747 до 0.531. Модель стала находить больше покупок, но вместе с этим выросло число ложноположительных прогнозов.

### H2. Масштабирование сильнее повлияет на Logistic Regression, чем на Random Forest

Гипотеза подтвердилась частично.

Для Logistic Regression изменение среднего ROC-AUC составило около 0.0027, а для Random Forest - около 0.00005. Дерево практически не отреагировало на масштабирование. При этом Logistic Regression без масштабирования показала немного лучший результат: 0.9057 против 0.9030. То есть линейная модель действительно оказалась чувствительнее, но масштабирование в этом эксперименте не улучшило качество.

### H3. Top-5 признаков по impurity importance и permutation importance будут отличаться

Гипотеза подтвердилась.

В двух списках совпали три признака: `PageValues`, `Month` и `ExitRates`. Остальные позиции различались. Это ожидаемо, потому что impurity importance оценивает использование признаков в разбиениях деревьев, а permutation importance смотрит, насколько падает качество после перемешивания признака.

### H4. Удаление `ExitRates` сильнее изменит Logistic Regression, чем Random Forest

Гипотеза подтвердилась частично.

У Logistic Regression изменение среднего ROC-AUC составило около 0.0015, у Random Forest - около 0.0002. При этом обе разницы небольшие. После удаления `ExitRates` результат Logistic Regression даже немного вырос: с 0.9030 до 0.9045. Вероятно, этот признак частично повторяет информацию, которая уже содержится в `BounceRates`.

### H5. Добавление категориальных признаков повысит ROC-AUC Logistic Regression

Гипотеза подтвердилась.

На одних числовых признаках средний ROC-AUC составил 0.8873. После добавления категориальных признаков он вырос до 0.9030. Полный набор признаков был лучше на всех пяти фолдах.

### H6. SelectKBest сократит число признаков без заметной потери качества

Гипотеза подтвердилась частично.

Лучший вариант `SelectKBest` оставил 15 признаков. Средний ROC-AUC почти не изменился: 0.9033 с отбором против 0.9030 без отбора. Значит, часть признаков можно убрать без заметной потери качества, но устойчивого улучшения модель не получила.

## Финальные результаты

| Модель | Accuracy | Precision | Recall | F1 | ROC-AUC | Average Precision |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Gradient Boosting | 0.901 | 0.717 | 0.605 | 0.656 | 0.937 | 0.750 |
| Random Forest | 0.881 | 0.590 | 0.788 | 0.675 | 0.934 | 0.745 |
| Logistic Regression | 0.853 | 0.519 | 0.806 | 0.632 | 0.913 | 0.666 |
| DummyClassifier | 0.844 | 0.000 | 0.000 | 0.000 | 0.500 | 0.156 |

Gradient Boosting показал самый высокий ROC-AUC, Average Precision и precision. Random Forest получил лучший F1 и при этом сохранил высокий recall. Logistic Regression показала самый высокий recall, но чаще ошибочно относила обычные сессии к покупательским.

Одной лучшей модели для всех случаев здесь нет:

- Gradient Boosting лучше подходит, если важнее точность положительных прогнозов;
- Random Forest даёт самый ровный баланс precision и recall;
- Logistic Regression находит больше всего покупок, но создаёт больше ложных срабатываний.

Высокая accuracy у `DummyClassifier` показывает, почему на этих данных нельзя смотреть только на accuracy: модель предсказывает отсутствие покупки для всех сессий и не находит ни одного положительного объекта.
