# Прогноз лояльности клиентов в Elo Merchant Category Recommendation

Проект выполнен по данным соревнования [Elo Merchant Category Recommendation](https://www.kaggle.com/competitions/elo-merchant-category-recommendation). Цель - предсказать числовую переменную `target`, отражающую лояльность клиента, по характеристикам карты, информации о продавцах и истории транзакций. Качество измеряется метрикой RMSE: чем она меньше, тем лучше модель.

Вся исследовательская часть, эксперименты и создание итогового файла находятся в [ноутбуке](notebooks/solution.ipynb).

## Данные

Исходные данные доступны на странице соревнования Kaggle. В работе используются следующие таблицы:

- `train.csv` - обучающая выборка с целевой переменной;
- `test.csv` - карты, для которых нужно построить прогноз;
- `historical_transactions.csv` - транзакции до контрольного периода;
- `new_merchant_transactions.csv` - транзакции из нового периода;
- `merchants.csv` - характеристики продавцов;
- `sample_submission.csv` - пример требуемого формата ответа.

Основная единица наблюдения в моделировании - карта (`card_id`). Таблицы транзакций предварительно агрегируются до этого уровня, поэтому одна строка признаковой матрицы соответствует одной карте.

## Ход исследования

Работа построена как последовательность проверяемых экспериментов, а не как единичный запуск модели.

1. Проведён EDA: изучены размеры и типы таблиц, пропуски, распределение `target`, активность по картам и различия между историческим и новым периодами.
2. Из транзакций сформированы признаки интенсивности и сумм покупок, долей авторизованных операций, рассрочки, разнообразия продавцов и категорий, временной активности и различий между двумя периодами.
3. В абляционных экспериментах сопоставлены группы признаков, чтобы оценить их вклад отдельно от выбора модели.
4. Для baseline использованы `DummyRegressor` и `RidgeCV`, затем обучены и настроены `LightGBM`, `XGBoost` и `CatBoost`.
5. Проверены дополнительные идеи: target encoding, коррекция экстремального сегмента `target`, усреднение XGBoost по нескольким `seed`, взвешенный blend и Ridge stacking.
6. По итогам сравнения выбрана схема, дающая устойчивый выигрыш относительно простой одиночной модели.

## Валидация

Для всех основных экспериментов используются одни и те же 5 фолдов `StratifiedKFold`. Стратификация построена по признаку `target < -30`, чтобы редкие экстремально низкие значения целевой переменной были представлены в каждом фолде. Качество сравнивается по out-of-fold RMSE.

Для сравнения ансамбля с лучшей одиночной моделью применён парный бутстрэп разности RMSE по OOF-прогнозам. Поэтому решение о финальной модели основано не только на минимальном значении метрики, но и на устойчивости различия.

## Результаты экспериментов

| Модель | OOF RMSE |
| --- | ---: |
| DummyRegressor | 3.850497 |
| RidgeCV | 3.842995 |
| LightGBM с подбором параметров | 3.661095 |
| XGBoost с подбором параметров | 3.642479 |
| CatBoost с подбором параметров | 3.645502 |
| XGBoost с усреднением по трём `seed` | 3.640658 |
| Взвешенный blend | 3.640409 |
| Ridge stacking | 3.640144 |

Минимальный OOF RMSE показал Ridge stacking. Его преимущество над XGBoost с усреднением по трём `seed` составило лишь `0.000514`, а доверительный интервал парной бутстрэп-разности включил ноль. Поэтому для итогового файла выбран более простой и воспроизводимый XGBoost bagging.

### Что улучшило качество

- Агрегация транзакций из обоих периодов дала основной прирост относительно признаков карты.
- Наиболее полезным оказался блок устойчивых признаков покупательской и календарной активности.
- Подбор параметров снизил OOF RMSE XGBoost с `3.655293` до `3.642479`.
- Усреднение прогнозов XGBoost по трём `seed` дополнительно улучшило OOF RMSE до `3.640658`.

### Что не дало устойчивого выигрыша

- Target encoding не улучшил настроенный XGBoost: `3.642831` против `3.642479`.
- Коррекция экстремального сегмента уменьшила ошибку на хвосте распределения, но ухудшила общий RMSE.
- Более сложные ансамбли показали минимальное численное улучшение, которого недостаточно для уверенного выбора вместо XGBoost bagging.

## Итоговый файл

Файл [submission_xgboost_seed_bagging.csv](submissions/submission_xgboost_seed_bagging.csv) содержит прогнозы для тестовой выборки в формате Kaggle. Скриншот отправки находится в [reports/kaggle_submission.png](reports/kaggle_submission.png).

На Kaggle итоговый файл получил public RMSE **3.69682** и private RMSE **3.61029**. По сохранённому private leaderboard это 132-е место из 4 111, или топ 3.21% участников.

## Запуск

1. Клонируйте репозиторий и переключитесь на ветку проекта:

   ```bash
   git clone https://github.com/GriGkos/ml-projects.git
   cd ml-projects
   git switch project/03-kaggle-feature-ensemble
   ```

2. Установите зависимости:

   ```bash
   pip install -r projects/03_kaggle_feature_ensemble/requirements.txt
   ```

3. Скачайте данные соревнования и разместите их в каталоге `data/` проекта. Для запуска в другой среде достаточно указать этот каталог в конфигурационной ячейке ноутбука через переменную `PROJECT_DIR`.

4. Откройте `notebooks/solution.ipynb` и выполните ячейки сверху вниз. Ноутбук последовательно выполняет EDA, построение признаков, кросс-валидацию, подбор параметров, эксперименты с ансамблями и создание submission-файла.

Расчёт использует GPU для обучения бустингов и обработки крупных таблиц транзакций. На CPU выполнение возможно после изменения параметров моделей, но займёт существенно больше времени.
